# KSE 물류 모션 연속성 감사

## 발견한 문제

1. 서비스 카피가 나타날 때 측면 트럭이 이미 주행 구간 중반에 진입해 있었다.
2. 리치 스태커와 측면 트럭이 높은 불투명도로 동시에 보여 충돌처럼 보였다.
3. 탑뷰 트럭과 선박의 최초 배율이 커서 `진입`보다 `이미 지나가는 중`처럼 보였다.
4. 전체 이동이 선형 이징 중심이라 스크롤에 정확히 붙지만 기계적으로 느껴졌다.

## 수정한 타임라인

| 장면 | 진입 | 주행 | 퇴장·전환 |
|---|---|---|---|
| 리치 스태커 | `power2.out`으로 접근 | 컨테이너 축 고정 | `power2.in`으로 먼저 퇴장 |
| 측면 트럭 | 스태커 퇴장 뒤 투명도 별도 상승 | 왼쪽에서 중앙을 충분히 통과 | 오른쪽으로 가속하며 탑뷰 전환 |
| 탑뷰 트럭 | 화면 아래에서 중앙으로 진입 | `power1.inOut`으로 위쪽 주행 | 같은 축의 선박으로 확대 매치컷 |
| 탑뷰 선박 | 기존보다 작은 배율로 화면 안에 진입 | 위쪽 이동과 축소를 동시에 진행 | 글로벌 카피 뒤에 잔류 |

## 역동성 보강

- `scrub` 완충값을 `0.35 → 0.7`로 늘려 스크롤 입력의 미세한 떨림을 줄였다.
- 도로 차선을 차량 반대 방향으로 스크롤 연동해 속도감을 만들었다.
- 선박 등장 시 항적이 점진적으로 길어지도록 했다.
- 구름은 선박과 다른 속도로 이동해 깊이감을 보강했다.
- 진입은 `ease-out`, 순항은 `ease-in-out`, 퇴장은 `ease-in`으로 역할을 분리했다.

## 브라우저 검증 결과

### 데스크톱

- 측면 트럭: 진행률 `14%`에서 화면 내 노출 약 `93%`, `18~24%`에서 완전 노출
- 탑뷰 트럭: 진행률 `46~52%`에서 완전 노출
- 선박: 진행률 `68%`에서 약 `66%`, `76%`에서 약 `71%`, `84%`에서 약 `95%` 노출

### 모바일 390px

- 측면 트럭이 진행률 `18%`에 왼쪽 진입 위치에서 보이기 시작한다.
- 탑뷰 트럭은 진행률 `46%`에 중앙에 머문다.
- 선박은 진행률 `68%`부터 화면 아래에서 나타나 `84%`에 카피와 결합한다.
- 가로 오버플로 없음.

## 접근성

`prefers-reduced-motion` 환경에서는 기존과 동일하게 긴 스크롤 무대를 제거하고 정적 단계 설명을 제공한다.
