## 핵심 모션 문법

레퍼런스의 핵심은 여러 섹션에 개별 애니메이션을 붙이는 방식이 아니다. 하나의 화물 오브젝트와 화면 중심축을 유지하면서 운송수단과 카메라 시점이 연속적으로 바뀌는 스크롤 시퀀스다.

1. 리치 스태커가 컨테이너를 들어 올린다.
2. 동일한 컨테이너가 트럭 섀시에 결합된다.
3. 측면 트럭이 서비스 목록과 함께 수평으로 이동한다.
4. 트럭이 확대되면서 측면 이미지에서 탑뷰 이미지로 매치 전환된다.
5. 세로 도로를 따라 트럭이 이동하며 신뢰성 메시지를 통과한다.
6. 흰 컨테이너 중심축을 유지한 채 트럭에서 선박 탑뷰로 전환된다.
7. 선박이 바다 위에서 축소되며 글로벌 메시지와 다음 섹션을 연다.

## 구현 방식 확인

- Webflow 마크업 위에 별도 Vite 번들이 로드된다.
- GSAP 기반 스크럽 타임라인과 Lenis 스크롤을 사용한다.
- 투명 AVIF 오브젝트와 탑뷰/측면 이미지를 장면별로 교체한다.
- 해상 구간은 Three.js 관련 모듈과 별도의 웨이크 시뮬레이션을 사용한다.
- 주요 오브젝트는 하나의 3D 모델만 회전시키는 것이 아니라, 시점에 맞춘 여러 자산을 정렬해 매치컷한다.

## KSE 프로토타입에 적용한 수정

- 기존 `Journey + Fulfillment + Customs + Transport`의 분리된 장식형 모션을 하나의 `FreightSequenceSection`으로 교체했다.
- 같은 흰 컨테이너와 네이비 장비를 사용한 리치 스태커, 측면 트럭, 탑뷰 트럭, 탑뷰 선박 자산을 GPT Image 2.0으로 새로 생성했다.
- 900svh 길이의 고정 무대에서 스크롤 진행도를 하나의 GSAP 타임라인에 연결했다.
- 트럭의 이동 구간에 KSE의 풀필먼트, 통관, 육상, 해상 서비스를 배치했다.
- 탑뷰 도로 구간에는 한국·일본 자체 인프라의 가시성을, 해상 구간에는 글로벌 파트너 네트워크를 연결했다.
- 모바일에서는 같은 시퀀스를 유지하되 가려지는 메시지에 독립 패널을 제공했다.
- `prefers-reduced-motion` 환경에서는 고정 무대를 제거하고 정적인 단계 목록을 제공한다.
